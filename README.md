# 云连接助手

<img src="assets/app-icon.png" alt="云连接助手图标" width="96" height="96">

macOS 原生 AppKit 窗口，用现有系统代理连接 Codex 云服务，提供可选的本机 HTTPS/SSE 中继、连接就绪后启动 Codex。使用 AppleScriptObjC 和 Python 标准库，没有新增第三方 Python 依赖。

## 下载 macOS App

[下载 v1.2.1 Apple Silicon 版](https://github.com/xinxinzai98/cloud-link-assistant/releases/download/v1.2.1/cloud-link-assistant-v1.2.1-macos-arm64.zip) · [发布页与校验文件](https://github.com/xinxinzai98/cloud-link-assistant/releases/tag/v1.2.1)

适用于 M 系列芯片 Mac。Releases 版内置 Python，无需另外安装 Homebrew 或 Python。解压 ZIP，将 App 拖入“应用程序”，开启已有系统代理后打开。Intel Mac 暂未提供经过验证的安装包。

升级已有版本时：

从 v1.2.0 升级到 v1.2.1 时，Codex 核心脚本未改变：可在助手选择“保留后台并退出”，保留原路径替换 App 后重开，继续使用现有中继与配置。更早版本按下述流程同步系统副本。

1. 已开启云中继自启的用户，先在旧版菜单选择“关闭开机自动启动…”（新版名称为“关闭云中继开机启动…”），退出窗口后替换原 App，再在新版菜单重新开启。这样会同时更新系统中的守护程序副本，仅替换 App 不会更新正在运行的系统副本。操作期间云连接会短暂重连，恢复记录保留。
2. 未开启自启的用户，先停止旧中继并退出窗口，再替换原 App、从新版启动。

旧版关闭自启时若提示“进程未响应但恢复尚未确认”，先刷新状态；只有确认“已停止”后，再执行一次“关闭开机自动启动…”并确认成功。若仍显示“需要恢复设置”，先完成恢复再继续升级。

保持原 App 路径和文件名，并保留旧状态目录及其恢复备份，直到停止和恢复设置都已确认完成。为兼容已登记的登录项，App 文件名保留“云连接助手 1.0.app”；实际版本号在“关于”窗口显示为 1.2.1。

已有独立安装的本机 HTTPS/SSE 中继时，在新版点一次“启用本机优化”即可接入管理、保存私有备份并更新后续启动代码。现有中继进程继续运行，待结束聊天后重启中继或下次开机加载新代码。不要在聊天运行期间选择“停止本机中继”。

App 使用临时签名，未完成 Apple 公证。若 macOS 提示无法验证开发者，请核对下载来源与校验值，再按 [Apple 的说明](https://support.apple.com/guide/mac-help/open-a-mac-app-from-an-unknown-developer-mh40616/mac)在“系统设置 → 隐私与安全性”中确认打开这个 App。

## 功能与系统改动

- 启动、停止、查询中继状态，异常后恢复自有设置。
- 仅监听 `127.0.0.1:443`，为 `codex-cloud-backend.chatgpt.com` 临时添加带标记的 hosts 映射。
- GUI 启动时只为 `Wi-Fi` 追加这一个域名的系统代理例外；停止时撤销自有项，保留其他配置。
- 开启自启守护后，运行中约每 10 秒核对本工具添加的域名例外，丢失时补回；保留当前其他例外，不接管用户原有的同域名例外。
- 通过回环地址的系统 HTTP 代理发送 CONNECT，透传 TLS 字节，保留客户端的 SNI 和证书校验。
- 通过代理查询加密 DNS，避免 hosts 映射导致上游连接绕回本机。
- 管理进程维护设置和恢复备份，网络转发进程以原普通用户运行。
- 可选启用本机 `127.0.0.1:19847` HTTPS/SSE 中继，只转发官方 `chatgpt.com/backend-api/codex` 的模型列表、Responses 与压缩端点；完整保留 TLS 证书及主机名校验，通过当前回环地址上的系统 HTTPS 代理连接，不回退直连。
- 本机优化只在 `~/.codex/config.toml` 添加 `openai_base_url = "http://127.0.0.1:19847"`，保留官方 `openai` 提供商、账号、模型及其他设置。已有其他提供商或自定义接口时拒绝自动覆盖。请求正文、图片和授权头只在内存转发，不写日志或凭据缓存。
- 本机中继使用普通用户 LaunchAgent。启用本机优化且开启云中继自启后，登录项会等待代理端口、两条中继、云域名解析及例外、两个官方域名的 TLS 校验通过，再打开助手和 Codex；已经运行的应用保持原样。

云中继启动、恢复系统设置及云中继自启需要 macOS 管理员授权；本机 HTTPS/SSE 优化使用当前普通用户，不需要管理员权限。关闭窗口保留后台；退出时可选择保留后台或停止全部中继。首次打开 App 不会自动改变连接配置；本机优化和云中继自启分别由用户明确启用。

## v1.2.1：精简连接功能

界面和安装包仅保留 Codex 云中继、本机 HTTPS/SSE 及就绪启动，移除其他软件的登录、授权网络检查和对应后台脚本。窗口同步缩小，Codex 中继和配置逻辑保持原样。

## v1.2.0：本机 HTTPS/SSE 与就绪启动

App 中新增“本机聊天 HTTPS/SSE”区域：

1. **启用本机优化**：安装用户级本机中继和登录自启，校验中继就绪后写入这一个官方提供商接口覆盖项。已开启云中继自启时，同时接入就绪启动顺序。重新打开 Codex 后统一生效。
2. **恢复原连接**：只撤销本工具的接口覆盖项，保留并发修改及其他配置；继续保留本机中继供已有聊天使用。完成任务并重开 Codex 后使用原连接方式。
3. **停止本机中继…**：确认后恢复配置、停止本机中继并关闭其用户级自启。仍使用旧中继地址的会话会中断，先结束聊天再操作。

云中继的“停止”按钮只停止云中继；退出面板中的“停止全部并退出”会恢复本机接口配置并停止两条中继。“保留后台并退出”保留两条中继。开关云中继自启不替用户切换本机优化设置。

本机中继先返回一次 WebSocket HTTP 426，使当前 Codex 客户端回退到 HTTP/SSE，再把模型请求发送到官方。日志中的这个本机 426 不代表最终聊天失败。中继只在请求尚未转发前重试建立上游连接；开始发送后不自动重放请求，流中断时不伪造完成事件。

后台脚本和私有备份分别保存在 `~/Library/Application Support/云连接助手/model-https-compat` 与 `~/.codex/backups/cloud-link-assistant/`。备份可能包含原配置中的私有字段，目录限制为当前用户访问，不纳入仓库和安装包。新版本可接管本助手此前的中继安装，拒绝接管未知的端口占用或自定义启动项。

## v1.1.2 修复

- 上游结束发送后及时释放连接名额，避免客户端暂不关闭时占满转发上限；客户端先半关闭时继续接收完整响应。
- 状态接口按换行读取完整回复，避免分包导致误报未运行；查询客户端先断开时不再产生未处理异常。关闭启动项时若守护已经开始停止，会等待恢复完成，避免过早报错。
- 连接错误保留计数，并记录发生时间、客户端或上游方向、操作和字节量；不记录 TLS 内容、请求正文、账号或令牌。客户端取消和上游断开均可能触发重置，计数本身不能证明云聊天掉线。
- 按上文先关闭自启、替换 App、再开启的顺序升级时，同步更新受保护的中继代码并保存旧代码；注册失败回退，运行中的旧中继拒绝被直接覆盖。原状态目录和 hosts 恢复记录保留。

这些修复已通过 44 项隔离回归。本机验收结束时，中继已连续运行约 74 分钟；其中约 5 分 20 秒的观察跨过一次 DNS 刷新，原有云聊天 8 次读取成功，无新增错误。新的长时间生成和休眠唤醒仍须单独验证，不能消除代理节点或服务端主动断开。

## 环境

- macOS，内置 `osacompile`、`codesign` 和 AppKit；本机使用 Python 3.14 验证，构建脚本要求 Python 3.11+。
- 已开启系统 HTTPS 代理，地址为 `127.0.0.1`、`localhost` 或 `::1`，代理支持 HTTP CONNECT。
- `127.0.0.1:443` 未被其他服务占用；GUI 当前按 `Wi-Fi` 网络服务处理代理例外。

上述 Python 与编译工具用于源码构建。默认源码构建复用指定的本机 Python；Releases 安装包随 App 打包可搬移的 Python 运行环境。

## 构建

```sh
python3 build.py
```

产物为 `dist/云连接助手 1.0.app` 和 `dist/云连接助手 1.0.zip`。已有产物不会被覆盖，可用 `--output` 指向新目录。构建只编译与签名，不启动 App 或中继。

```sh
python3 build.py --python /absolute/path/to/python3 --output /absolute/path/to/new-output
```

制作可直接下载使用的安装包时，传入完整的可搬移 Python 目录。程序会把解释器、标准库和上游许可证一起复制进 App；运行时按 App 所在位置寻找内部解释器。

```sh
python3 build.py --bundle-python /absolute/path/to/standalone/python --output /absolute/path/to/new-output
```

随包运行环境来源、版本和 SHA-256 见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。打包采用 `ditto`，保留运行环境的符号链接和可执行权限。

App 使用 `assets/appicon.icns`，包含 16–1024 像素图标；原始 PNG 和 imagegen 提示词也保存在 `assets/`。构建时撤除脚本模板的图标目录引用，并验证签名。

默认不探测其他目录中的旧中继。需要接管既有中继时，在保留原状态目录及其恢复备份的前提下构建：

```sh
python3 build.py --legacy-state /absolute/path/to/existing/.state
```

路径只嵌入本机构建产物，源码不包含个人目录。新启动的状态目录为：

```text
~/Library/Application Support/云连接助手/relay-state
```

## 使用

1. 开启现有代理客户端的系统代理，无需 TUN。
2. 打开构建出的 App，查看状态后按需启动，并在系统窗口输入管理员密码。
3. 停止中继后，程序撤销自有 hosts 映射和代理例外。
4. 若显示“需要恢复设置”，保留状态目录和备份，使用“恢复设置”。


## 开机自动启动（可选）

首次使用先在 App 中成功启动一次云中继，再在“云连接助手”菜单选择“开启云中继开机启动…”或“关闭云中继开机启动…”，由系统窗口完成管理员验证。下载版已包含原生菜单和安装组件。也可使用仓库中的 `autostart.py` 和两个 `.command` 文件。双击 [开启开机自动启动.command](开启开机自动启动.command)，或传入 App 路径：

```sh
zsh ./开启开机自动启动.command "$HOME/Applications/云连接助手 1.0.app"
```

首次需要输入一次管理员密码。安装使用 macOS 原生 LaunchDaemon 和用户 LaunchAgent：开机后等待指定用户登录、现有系统代理就绪，再启动同一个云中继。未启用本机优化时，登录时打开助手窗口；已启用本机优化时，等待两条中继就绪后再打开助手和 Codex。云中继等待期间每 15 秒重试，不回退直连。就绪启动检测到本机装有 Clash Verge 且未运行时，会请求在后台打开该应用；不修改它的代理、规则、节点或 TUN 设置，其他代理客户端保持原样。

系统执行的 Python、脚本和状态位于 root 所有且普通用户不可写的 `/Library/Application Support/CloudLinkAssistant`。原状态目录和全部恢复记录会整体迁移，原路径保留链接，现有 App 的启动、停止和恢复按钮继续使用同一份状态。安装时现有中继会短暂重连；转发进程仍以原普通用户运行。

手动停止后本次开机保持停止，下次重新开机再自动启动。启动进程异常退出时由系统重试；关闭助手窗口会保留后台。开机启动不保证代理额度、节点或外部网络持续可用。

v1.1.1 修复了运行中域名例外被改写后不会自动恢复的问题。已开启自启时，手动“启动”也会调用同一个系统守护服务；手动停止后不继续补回例外。未开启自启时仍沿用原手动启动方式，不会擅自安装启动项。

关闭自动启动可使用 App 菜单或 [关闭开机自动启动.command](关闭开机自动启动.command)。它卸载两个启动项并停止中继，撤销自有网络设置；系统副本和全部恢复记录保留，App 仍可手动启停，也可再次开启自动启动。

## Codex 本地聊天与云端兼容

本地聊天遇到 `Broken pipe` 或反复重连时，可使用仓库中的 [通过系统代理启动Codex.command](通过系统代理启动Codex.command)。它读取当前回环地址上的系统 HTTPS 代理，为新启动的 Codex 客户端传入进程级代理环境。

使用前，确认用户级 `~/.codex/config.toml` 的默认 `model_provider` 为官方 `"openai"`（也可不写该项）。当前排查的桌面版本会在全局默认提供商改为自定义 HTTP/SSE 提供商时隐藏云端入口，即使自定义提供商仍使用官方接口。脚本不自动修改配置文件。

1. 开启系统代理，需要云聊天时同时保持云连接助手中继运行。
2. 等正在运行的任务完成，按 `⌘Q` 完整退出 Codex 主客户端。
3. 双击启动脚本，再分别检查本地连续回复、原云聊天读取及新建聊天的云端入口。

脚本当前查找 `/Applications/ChatGPT.app`；如果客户端安装在其他位置，先调整脚本中的 `app_target`。仅做配置检查可运行：

```sh
zsh ./通过系统代理启动Codex.command --check
```

脚本保留现有直连范围，并合并系统代理例外，使 `codex-cloud-backend.chatgpt.com` 继续进入单域名中继。它不强制退出客户端、不改 hosts 或系统代理、不设置全局 `launchctl` 环境。代理变量只在本次启动中传入，之后直接从 Dock 启动不保证沿用这些变量。该脚本目前随源码提供，已发布的 v1.0.0 App ZIP 不包含此新增入口。

### 登录后等待连接就绪

`login_ready.py` 已随 v1.2.0 App 打包，由“启用本机优化”和云中继自启共同接入。它先等待系统代理、云中继的解析及代理例外、本机 HTTPS/SSE 中继和两个官方域名的 TLS 校验通过，之后打开助手，并沿用上述代理启动脚本打开 Codex。程序不读取登录凭据，不重启现有客户端或中继；手动停止中继后也不会将其重新拉起。

只检查就绪状态、不打开任何应用：

```sh
python3 -B login_ready.py --helper-app /absolute/path/to/云连接助手\ 1.0.app --check
```

登录启动时不加 `--check`，将本文件和 `通过系统代理启动Codex.command` 放在同一目录。网络未就绪时最多等待 10 分钟；超时不自动打开 Codex，保留手动入口。已经运行的应用保持原样，登录等待程序完成后退出，不会在用户关闭 Codex 时再次打开它。

macOS 的“重新登录时重新打开窗口”以及手动提前打开 Codex 都可能绕过这个等待入口。重启前先退出 Codex，或取消系统的该复选框；本程序不修改其他应用的窗口恢复设置。v1.2.0 重新开启云中继自启时，会保留已启用的就绪启动。旧版安装器可能覆盖新登录项，应保留安装和恢复记录。

2026-10-23 的受控测试中，官方默认提供商加显式代理环境完成了 5 次真实回复，其中一次在空闲 45 秒后继续；未显式传入代理的对照测试出现重连。客户端重启后已核对本地后台带有代理环境，原云聊天读取成功，短时客户端日志未发现同类 `Broken pipe`。这些结果不代表已验证长期使用、休眠唤醒或所有网络条件下都稳定，新建云端入口仍需在界面中确认。

## 验证

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s . -p 'test_*.py' -q
```

源码现有 69 项隔离测试，覆盖原云中继的恢复、TLS 透传、连接生命周期与自启策略，以及本机中继的压缩正文与授权头透传、实时 SSE、分块请求、模型缓存 304、压缩端点、截断不重放、接口配置保留、安装回退、并发编辑保留、已有中继接入、未知端口拒绝、恢复与停止、就绪等待和自启重装。测试使用临时目录与本地随机端口；不修改真实 hosts、Wi-Fi 设置或账号，也不重启现有聊天。

构建通过与隔离测试通过不等于真实管理员首启、长期云连接验收通过。现有用户环境下仍可能因代理和网络中断而重连。

## 源码

- `main.applescript`：原生窗口、状态与启停入口；解释器和可选旧状态路径由构建时填入。
- `relay.py`：固定域名的 CONNECT 中继与设置恢复。
- `通过系统代理启动Codex.command`：以现有系统代理启动 Codex 的可选入口，保留系统代理例外。
- `https_compat.py`、`test_https_compat.py`：仅回环监听、固定官方上游的模型 HTTPS/SSE 中继与隔离验证。
- `model_service.py`、`test_model_service.py`：本机优化的用户级安装、私有备份、恢复、启停和自启接入。
- `login_ready.py`、`test_login_ready.py`：连接就绪后打开助手及 Codex，以及对应的隔离验证。
- `build.py`：编译、临时签名和打包。
- `autostart.py`：系统启动项安装、代理等待及可恢复关闭；两个开关 `.command` 文件为入口。
- `THIRD_PARTY_NOTICES.md`：随包 Python 的来源与许可证位置。
- `test_relay.py`、`test_autostart.py`：隔离测试。

Git 只保存源码与说明。运行日志、hosts 备份、账号信息、OAuth 回调、地区申请材料、截图和 App 产物不纳入仓库。
